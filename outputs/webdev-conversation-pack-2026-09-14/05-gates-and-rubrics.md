# 规格 Gate 与页面 Rubric

## A. 正式生成前：Spec Gate

Gate 检查规格是否共同指导实现，不以 Markdown 长度或字段数量评判。

| 文件 | 必查 |
|---|---|
| product-intent.md | 用户场景、业务前提、核心任务、成功条件、范围、非目标、必要状态、假设 |
| design.md | 主次参考、COPY/ADAPT/IGNORE、任务到区域、Foundation、响应式、素材条件、优先级与容差 |
| component.md | 职责、组成、输入输出、事件、状态所有权、依赖、恢复、参数绑定及验收 |

跨文件必查：
1. 每个核心任务有区域、组件和完成方式。
2. 每个必要状态有归属、触发、UI 表现和退出/恢复路径。
3. 关键事件有接收者且负载满足接收方。
4. Design 关键参数落实到组件，不重复定义冲突值。
5. 重排后必要内容和操作仍然可达。
6. 必须要求有明确验收方法。

例：选日期并预订 → 预订区域 → 日期输入/价格摘要/按钮 → 未选择/查询中/可预订/不可预订/错误 → 日期变更/查询/更新/提交 → 成功与失败路径检查。

READY：核心规格完整一致。
READY_WITH_CONDITIONS：有可执行默认值、允许降级或明确验证边界。
BLOCKED：业务分支、核心结构、事件或状态契约存在影响实现的未决冲突。

字体替代和推导断点不自动阻塞；采用记录的项目默认值后验证。素材缺失按方案是否依赖素材判定。Gate 通过不代表页面已经通过。

## B. 页面验收：从 Visual Contract 生成

比较前固定 viewport/DPR、裁切、滚动、主题、语言、数据与状态，等待字体图片稳定。

| 维度 | 关注项 | 方法 |
|---|---|---|
| 布局比例 | 区域顺序、容器、列、图像比例、视觉重心 | DOM + 同条件截图 |
| 文字密度 | 字体角色、层级、行高、换行、留白 | 样式量测 + 截图 |
| 组件细节 | 尺寸、边框、圆角、颜色角色、状态样式 | 组件对比 |
| 内容素材 | 加载、裁切、协调性、真实性、视觉重量 | 文件 + 视觉审查 |
| 任务状态 | 核心操作、数据同源、错误恢复、反馈 | 实际操作 |
| 跨端与操作 | 重排、溢出、遮挡、键盘、焦点、减少动效 | 边界尺寸 + 操作 |
| 参考身份 | 关键设计关系仍在、无无关装饰或平均风格 | 有证据整体评审 |

COPY 对照参考；ADAPT 对照适配约定；IGNORE 不进入还原评判。
默认 P0 为宏观比例/层级/间距/密度，P1 为组件与视觉层次，P2 为装饰；可按任务调整。priority 与 blocking 分开。

## C. 最小规则结构

```yaml
id: SPEC-TASK-COVERAGE
scope: cross_document
severity: blocking
requirement: 每个核心任务都有完整实现映射
inputs:
  - product_intent.required_tasks
  - design.regions
  - components
  - acceptance_checks
checks:
  - 每个任务映射承载区域
  - 区域包含必要组件
  - 关键事件有接收者
  - 成功与失败路径有验收项
failure_output:
  - 缺失任务或关系
  - 文件与位置
  - 最小修正建议
```

视觉规则还要有 region、COPY/ADAPT、来源精度、视口、状态、目标、容差、单位、检查方法、修复范围和保留项。容差在实现前定义，不能为通过而事后放宽。截图推测值不伪装成精确量测。

结果另存 rule_id、run_id、page、viewport、state、status、actual、evidence、repair_target。
统一结果使用 PASS/FAIL/UNVERIFIED/NOT_APPLICABLE；未执行项可由 execution_status=not_run 区分。历史不同状态枚举应在导入边界转换，不让多个枚举混用。

## D. 四个节点

生成前：参考、状态、参数、素材和跨文件闭合。
骨架后：P0 比例、层级、密度。
素材与交互后：任务、状态、真实素材、跨端与可达性。
交付前：重拍截图、参考身份、剩余偏差与范围。

## E. 通过与修复

P0 全过；重要 P1 已修复或有明确接受记录；核心任务、必要状态、声明支持的端已检查。必需项 UNVERIFIED 不宣称全面通过。结构行为与完整视觉分别报告。

每条差异：区域 → 预期 → 实际 → 证据 → 原因 → 修改 → 回归。
每轮聚焦少量高影响项；连续两轮无改善进行根因分析。预算耗尽不等于通过。

通过率 = PASS / 全部适用项；同时显示未验证率与阻塞项。禁止称为“视觉相似度”。规则检查得分不等于业务质量，更不能覆盖硬约束失败。

上游变更后，重跑受影响 Gate 并重新编译 Query/Prompt。模型语义审查与程序确定性检查互补；不要让模型为宣布完成自行改判据。
