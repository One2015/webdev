# 从参考学习样式

把参考中有辨识度的视觉选择，转成适合当前内容的具体改动。默认用中文简短沟通，直接完成用户要求的设计调整或 HTML 内容。

## 先看参考与目标

实际查看参考图或页面，以及待优化的设计、HTML 或项目相关文件。Forge、Copula Lab 是用户的目标名称，不预设它们的技术栈、品牌规范或页面结构；从当前任务提供的材料确定。

用户只要求学习、分析或建议时，输出短小的样式总结或修改建议，不改文件。要求优化或制作时，完成实际修改。缺少目标材料且无法从当前上下文找到时，只问具体缺失项；仍可先分析已有参考。没有查看参考就不能声称已提取其样式。

## 用几句话抓住样式

默认提炼 3–5 个真正影响观感的特征，选择与任务相关的项：

- 构图：对齐方式、内容宽度、留白、分区、疏密和视觉重心。
- 文字：标题与正文的大小关系、字重、行距、行宽，以及中文排版适配。
- 色彩：背景、文字、强调色的角色、对比和使用面积。
- 细节：边框、圆角、阴影、图标、图片裁切与图文比例。
- 个性：具体是什么让参考有辨识度，转成可实现的规则，不只说“高级”“简洁”。

例如：“大标题配窄正文；暖灰底与细分隔线；卡片阴影很轻；强调色只用于关键动作。”

尺寸和字体无法确认时标记为估计，不伪装成精确测量。多张图默认以一张为主，其他图只补明确的局部特征，避免混成平均风格；用户指定的组合优先。

## 直接用于当前设计或 HTML

先简短说明准备采用的样式特征，然后继续工作，不等待逐项确认。

- 保留目标的内容语义、核心信息、既有品牌与功能。参考用于学习视觉方法，不自动复制品牌、无关功能或整页布局。
- 优化 Forge / Copula Lab 时先沿用现有结构和样式约定，围绕用户指定区域调整排版、间距、颜色和细节；不因为参考不同就重建项目。
- 制作 HTML 内容时按内容选择结构，例如文章、说明页、展示卡片或报告；内容优先，长短和层级决定排版。没有既定工程时，优先简洁的 HTML/CSS；不默认引入框架、组件库、后端或构建流程。
- 将本次重复使用的颜色、字体和间距集中成少量变量即可，不要求建立完整 Design System 或 token 文档。
- 只有用户要求高度复刻时才更细地追踪尺寸与比例。一般任务追求风格准确、内容可读与整体协调。
- 不默认添加动画、额外页面或新功能。只在任务需要时使用其他工具或 skill；不自动串联完整 webdev 流程。

## 看一次实际效果，修明显问题

有可用预览环境时查看实际结果，关注是否表达了刚才提炼的特征，以及文字是否拥挤、层级是否清晰、内容是否被裁切或溢出、既有操作是否受影响。按任务涉及的屏幕检查即可，不默认执行多端矩阵或评分报告。

修复明显偏差后交付。涉及交互改动时验证对应操作；纯视觉小改不扩展成全面测试。没有运行或预览条件时如实说明，不能声称已经视觉验证。

默认最终只需：结果或文件链接、采用了哪些关键样式、必要的未验证项。无需长篇设计说明、契约文件或检查表。

## 日常积累

“学习”首先指本次从参考中提炼并应用。若用户要求保存风格，在项目内记录一张简短样式卡：参考来源、3–5 条风格规则、适合的内容、应避免的用法；以后做相似内容时复用。不要自动把一次偏好变成所有项目的永久规则，也不宣称会自动记住未保存的历史。

用户明确要求完整产品原型、完整 pipeline 或多端系统设计时，按新范围处理；当前环境若有更适合的 skill 可以选用，本 skill 不依赖它们。
